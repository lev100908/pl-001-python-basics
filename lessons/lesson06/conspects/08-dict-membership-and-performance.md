# Поиск в словаре: оператор in и производительность

> **Главная мысль.** Оператор `key in my_dict` проверяет, есть ли **ключ** в
> словаре, и возвращает `bool`. Для словарей эта проверка выполняется
> практически за **одно и то же время вне зависимости от размера словаря**,
> потому что Python по хешу ключа сразу находит нужное место. В списке же
> `in` последовательно сравнивает искомое значение с элементами, поэтому
> время поиска растет вместе с длиной списка. Для больших объемов данных
> разница достигает многих порядков.

---

## 1. Оператор `in` для словарей

Оператор `in` проверяет наличие **ключа** в словаре, а `not in` — его
отсутствие. Результат — значение типа `bool`:

```python
user = {"name": "Alice", "age": 25}

print("name" in user)      # True
print("city" in user)      # False
print("city" not in user)  # True
```

Оператор проверяет именно **ключи**, а не значения:

```python
print("Alice" in user)  # False -- "Alice" является значением, а не ключом
```

Чтобы искать среди **значений** или **пар**, применяют `in` к
соответствующим представлениям словаря:

```python
print("Alice" in user.values())     # True
print(("age", 25) in user.items())  # True
print(("age", 30) in user.items())  # False
```

Но стоит помнить, что поиск в `values()` — это перебор значений один за
другим (как в списке), поэтому он медленный. Быстрой является только
проверка по **ключу**.

Проверка `in` пригодится перед обращением к ключу, когда нужно по-разному
обработать случаи «есть» и «нет», а также когда в словаре может лежать
`None` (тогда `get()` не позволяет отличить «ключа нет» от «значение
`None`»):

```python
settings = {"theme": "dark", "timeout": None}

if "timeout" in settings:
    print("Timeout is configured:", settings["timeout"])

else:
    print("Timeout is not configured")
```

Вывод:
```
Timeout is configured: None
```

## 2. Почему поиск в словаре быстрее, чем в списке

**Список.** Оператор `value in my_list` выполняет **линейный поиск**: берет
элементы по одному с начала списка и сравнивает каждый с искомым значением.
Если значения в списке нет, придется просмотреть **все** элементы. Чем
длиннее список, тем дольше поиск: время пропорционально количеству элементов
(в терминах теории алгоритмов — `O(n)`).

**Словарь.** Оператор `key in my_dict` вычисляет **хеш** ключа и по нему сразу
определяет ячейку хеш-таблицы, где ключ должен лежать (см. конспект про
хеш-функции). Остальные пары не просматриваются. Поэтому время поиска
практически **не зависит** от размера словаря (`O(1)` в среднем).

Сравним на практике. Для замера времени воспользуемся функцией `timeit` из
стандартного модуля `timeit`: она многократно выполняет заданное выражение и
возвращает суммарное время в секундах. Будем искать число, которого в
коллекциях заведомо нет (это худший случай для списка — просматриваются все
элементы):

```python
from timeit import timeit

search_repeats = 100  # сколько раз повторяем поиск

for items_count in (1_000, 100_000, 1_000_000):
    numbers_list = list(range(items_count))
    numbers_dict = dict.fromkeys(numbers_list)
    missing_number = -1

    list_time = timeit("missing_number in numbers_list", globals=globals(), number=search_repeats)
    dict_time = timeit("missing_number in numbers_dict", globals=globals(), number=search_repeats)

    print(f"{items_count:>9} items | list: {list_time:.6f} s | dict: {dict_time:.6f} s")
```

Пример вывода (точные значения зависят от компьютера):
```
     1000 items | list: 0.000711 s | dict: 0.000003 s
   100000 items | list: 0.074992 s | dict: 0.000005 s
  1000000 items | list: 0.785587 s | dict: 0.000005 s
```

Что видно из результатов:

- время поиска в **списке** растет пропорционально его длине: список
  длиннее в 100 раз — поиск дольше примерно в 100 раз;
- время поиска в **словаре** практически не меняется при росте размера с
  тысячи до миллиона элементов;
- при миллионе элементов поиск в словаре оказывается быстрее поиска в списке
  более чем в сто тысяч раз.

### Когда это важно

Разницу на нескольких десятках элементов вы не заметите. Она становится
критичной, когда:

- данных много (тысячи, миллионы элементов);
- поиск выполняется **многократно**, например, внутри цикла — тогда
  медленный поиск в списке умножается на количество итераций.

В таких ситуациях, если нужна проверка «есть ли элемент», данные лучше
хранить в словаре (или в множестве — об этом в конспектах про множества).
Платой за скорость является память: хеш-таблица занимает больше места, чем
список с теми же элементами.

---

## Вывод

- `key in my_dict` проверяет наличие **ключа** (не значения) и возвращает
  `bool`; `not in` проверяет отсутствие. Для поиска по значениям или парам
  используют `in my_dict.values()` и `in my_dict.items()`.
- Проверка ключа в словаре выполняется за примерно постоянное время — по
  хешу ключа; поиск в списке — линейный, время растет с его длиной.
- На больших данных поиск по ключу в словаре быстрее поиска в списке на
  порядки, поэтому для частых проверок на принадлежность лучше выбирать
  словарь (или множество).
