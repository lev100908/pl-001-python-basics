# Создание кортежей

> **Главная мысль.** Кортеж чаще всего создают литералом через запятую
> (скобки `()` — необязательны, а вот **запятая обязательна**) или
> встроенным объектом `tuple()` из любого итерируемого объекта. Кортежные
> включения по смыслу существуют, но записываются не так, как ожидается —
> подробнее в разделе про включения.

---

## 1. Кортежный литерал

Кортеж создается перечислением элементов через запятую. Круглые скобки
традиционно используются для наглядности, но не обязательны. При создании кортежа
обязательны именно **запятые**:

```python
coordinates = (10, 20)
coordinates_without_parentheses = 10, 20

print(coordinates)                                     # (10, 20)
print(coordinates_without_parentheses)                 # (10, 20)
print(coordinates == coordinates_without_parentheses)  # True
```

---

## 2. Важность запятых в литералах

### Кортеж из одного элемента

Круглые скобки сами по себе не создают кортеж — в выражении `(42)`
скобки играют роль обычных группирующих скобок (как в арифметике), и
результат — просто `int`. Чтобы получить кортеж из одного элемента,
после значения обязательно нужна **запятая**:

```python
not_a_tuple = (42)
single_item_tuple = (42,)

print(type(not_a_tuple))        # <class 'int'>
print(type(single_item_tuple))  # <class 'tuple'>
print(single_item_tuple)        # (42,)
```

### Пустой кортеж — исключение

Пустой кортеж — единственный случай, где кортеж создается именно
скобками, без всякой запятой (одиночная запятая `,` без элементов — это
не литерал, а просто разделитель, и сама по себе кортеж не создает):

```python
empty_tuple = ()

print(type(empty_tuple))  # <class 'tuple'>
```

### Кортеж из нескольких элементов

При двух и более элементах запятая нужна только как разделитель между
ними — здесь никакой путаницы с группирующими скобками не возникает:

```python
several_items_tuple = (1, 2, 3)

print(several_items_tuple)  # (1, 2, 3)
```

---

## 3. Встроенный объект `tuple()`

Встроенный объект `tuple()` позволяет создавать кортеж из любого итерируемого
объекта по тому же принципу, что и `list()`:

```python
tuple("abc")      # ('a', 'b', 'c')
tuple([1, 2, 3])  # (1, 2, 3)
tuple(range(5))   # (0, 1, 2, 3, 4)
tuple()           # () -- пустой кортеж, без аргументов
```

`tuple()`, примененный к уже существующему кортежу, возвращает **тот же
самый объект**, а не его копию — в отличие от `list()`, примененного к
списку. Это возможно именно потому, что кортеж неизменяем: копировать
неизменяемый объект незачем, ведь его содержимое в любом случае никогда
не поменяется:

```python
original_tuple = (1, 2, 3)
same_tuple = tuple(original_tuple)

print(same_tuple is original_tuple)  # True -- это буквально один и тот же объект
```

---

## 4. Кортежные включения

Синтаксис `(выражение for переменная in источник)`, по аналогии со
списковыми включениями, создает **не кортеж**, а отдельный тип данных —
генератор (об этом мы подробнее поговорим далее в курсе). Чтобы получить именно кортеж,
нужно передать это выражение в `tuple()`:

```python
squares_generator = (number ** 2 for number in range(1, 6))
squares_tuple = tuple(number ** 2 for number in range(1, 6))

print(type(squares_generator))  # <class 'generator'>
print(squares_tuple)            # (1, 4, 9, 16, 25)
```

Все остальные правила: использование `if` для фильтрации, несколько
`for` для вложенных источников — работают точно так же, как и в
списковых включениях (см. конспект «Создание списков»).

---

## Вывод

- Кортеж создает **запятая**, а не скобки: `10, 20` и `(10, 20)` —
  одно и то же; скобки — только для наглядности и группировки.
- Кортеж из одного элемента требует запятую после значения (`(42,)`),
  иначе скобки воспринимаются как обычные группирующие. Пустой кортеж —
  исключение: создается именно `()`, без запятой.
- `tuple()` создает кортеж из любого итерируемого объекта; примененный к
  уже существующему кортежу, возвращает тот же самый объект — копирование
  не нужно из-за неизменяемости.
- Синтаксис `(... for ... in ...)` создает не кортеж, а генератор; кортеж
  из него получают явным вызовом `tuple(...)`.
