# Операции сравнения и логические операции

> **Главная мысль.** Операции сравнения (`== != < > <= >=`) сравнивают
> значения чисел и могут объединяться в **цепочки**. Логические операторы
> `not`, `and`, `or` работают по правилам проверки истинности, а `and`/`or`
> — **ленивые (short-circuit)**: они вычисляют второй операнд, только если
> это действительно необходимо, и возвращают не обязательно `bool`, а один
> из самих операндов.

---

## 1. Операции сравнения

Python поддерживает стандартный набор операций сравнения:

| Оператор | Значение |
|---|---|
| `==` | равно |
| `!=` | не равно |
| `<` | меньше |
| `>` | больше |
| `<=` | меньше или равно |
| `>=` | больше или равно |

Результат любой операции сравнения — всегда объект типа `bool` (`True` или
`False`):

```python
5 == 5  # True
5 != 3  # True
3 < 5   # True
5 <= 5  # True
```

Между собой можно сравнивать значения объектов разных числовых типов
— они приводятся так же, как и в арифметике (см. предыдущий конспект):

```python
1 == 1.0     # True  -- int и float сравниваются по значению
True == 1    # True  -- bool и int
0 == False   # True
```

## 2. Цепочки операций сравнения

Операции сравнения можно объединять в **цепочку**, записывая несколько
сравнений подряд — это распространенный и лаконичный способ проверить,
что значение лежит в диапазоне:

```python
number = 5

1 < number < 10       # True  -- эквивалент (1 < number) and (number < 10)
0 <= number <= 100    # True
10 > number >= 5      # True
```

Цепочки не ограничены только `<`/`>`/`<=`/`>=` — в них можно свободно
использовать `==`/`!=`, а также смешивать разные операторы сравнения между
собой в одной цепочке:

```python
value = 5

0 < value == 5     # True  -- эквивалент (0 < value) and (value == 5)
value == 5 != 6    # True  -- эквивалент (value == 5) and (5 != 6)
```

Точно так же в цепочку можно включать и `is`/`is not`: с
точки зрения грамматики языка `==`, `is`, `<` и другие перечисленные выше
операторы — это всё «операторы сравнения», и любые их комбинации можно
свободно объединять в одну цепочку:

```python
first_value = None
second_value = None

first_value is None is second_value  # True -- эквивалент (first_value is None) and (None is second_value)
```

Важная деталь: цепочка `a < b < c` эквивалентна `(a < b) and (b < c)` по
результату, но **не идентична ей буквально** — средний операнд (`b`)
вычисляется **только один раз**, а не дважды, как было бы при ручном
переписывании через `and`. Это не только короче по записи, но и
эффективнее, если вычисление операнда — не бесплатное:

```python
def get_value():
    print("computing...")
    return 5

# Здесь get_value() вызовется всего один раз:
print(1 < get_value() < 10)
```

## 3. Логические операторы: `not`, `and`, `or`

Логические операторы работают не только с `bool`, а с **любыми**
объектами — по тем же правилам проверки истинности (truth value testing),
которые уже разбирались применительно к `if`/`while`.

### `not` — логическое отрицание

`not` принимает один операнд, определяет его истинность по тем
же правилам truth value testing, что и `if`/`while`, после чего вычисляет
отрицание полученного логического представления: если операнд
**истинен**, `not` возвращает `False`; если операнд **ложен** —
возвращает `True`. То есть `not` проверяет истинность операнда и на основе этого
вычисляет новый объект типа `bool`, значение которого противоположно
истинности операнда.

`not` — единственный из трех операторов, который **всегда** возвращает
настоящий `bool` (`True` или `False`), вне зависимости от типа операнда:

```python
not True     # False
not 0        # True   -- 0 ложно, поэтому not 0 -> True
not ""       # True   -- пустая строка ложна
not "hello"  # False  -- непустая строка истинна
```

### `and` и `or` — не то же самое, что "логическое И/ИЛИ" в других языках

`and` и `or` тоже проверяют истинность операнда по правилам truth value
testing, но, в отличие от `not`, не вычисляют на основе этой проверки
новый объект `bool` — они лишь **выбирают**, какой из двух операндов
вернуть «как есть», без каких-либо преобразований:

- у `and` результат определяется первым ложным операндом: если `a`
  ложен, дальше проверять нечего — возвращается сам `a`; если `a`
  истинен, итог зависит от `b`, поэтому возвращается `b`;
- у `or` результат определяется первым истинным операндом: если `a`
  истинен, возвращается сам `a`; если `a` ложен, итог зависит от `b`,
  поэтому возвращается `b`.

Из-за этого `and` и `or` возвращают **не обязательно `bool`** — их
результатом становится объект того типа, каким был выбранный операнд:

```python
5 and 10  # 10 -- 5 истинно -> результат "переходит" на b
0 and 10  # 0  -- 0 ложно -> результат -- сам a, до b не дошли

5 or 10  # 5  -- 5 истинно -> результат -- сам a
0 or 10  # 10 -- 0 ложно -> результат "переходит" на b
```

## 4. Ленивость (short-circuit evaluation) `and` и `or`

`and` и `or` вычисляют операнды **по порядку, слева направо**, и
останавливаются, как только результат уже понятен — **второй операнд
может не вычисляться вовсе**. Это и называется ленивым (short-circuit)
вычислением.

```python
def noisy(name, value):
    print(f"computing {name}")
    return value

noisy("a", False) and noisy("b", True)
# computing a
# noisy("b", ...) НЕ вызывается -- a уже ложно, результат and предрешен

noisy("a", True) or noisy("b", True)
# computing a
# noisy("b", ...) НЕ вызывается -- a уже истинно, результат or предрешен
```

Ленивость — не просто оптимизация, на нее часто **опираются** в коде,
чтобы избежать ошибок: например, чтобы не обращаться к атрибуту `None`
или не делить на потенциально нулевой знаменатель:

```python
user = None

if user is not None and user.is_active:  # user.is_active НЕ проверится,
    print("active")                      # если user -- None: до AttributeError
                                         # дело не дойдет

divisor = 0

if divisor != 0 and (10 / divisor > 1):    # деление на 0 не произойдет
    print("greater than one")
```

Если бы `and` не был ленивым, а вычислял бы оба операнда всегда, оба примера
выше приводили бы к исключениям (`AttributeError`, `ZeroDivisionError`).

## 5. Приоритет операторов

Среди логических операторов приоритет такой: `not` выполняется раньше
`and`, `and` — раньше `or`. Операции сравнения имеют более высокий
приоритет, чем все три логических оператора.

```python
True or False and False  # эквивалент True or (False and False) -> True
not True == False        # эквивалент not (True == False) -> not False -> True
```

При смешивании нескольких операторов в одном выражении для читаемости
лучше расставлять скобки явно, не полагаясь на то, что читающий код
помнит точный приоритет операторов.

---

## Вывод

- Операции сравнения (`== != < > <= >=`) возвращают `bool` и допускают
  сравнение значений разных числовых типов.
- Сравнения можно объединять в **цепочки** (`1 < x < 10`) — это компактнее
  и, в отличие от ручного `and`, вычисляет общий операнд лишь один раз.
- `not` всегда возвращает `bool`; `and`/`or` возвращают один из своих
  операндов, а не обязательно `bool`.
- `and`/`or` **ленивы**: второй операнд вычисляется, только если первого
  не хватает для определения результата — на этом часто строят защитные
  проверки (`x is not None and x.method()`).
- Приоритет: `not` > `and` > `or`; сравнения приоритетнее всех логических
  операторов. В сложных выражениях лучше использовать скобки.
