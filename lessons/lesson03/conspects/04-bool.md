# Логический тип данных `bool`

> **Главная мысль.** `bool` — тип для логических значений `True` и `False`.
> Это **подтип `int`**: под капотом `True` — это `1`, а `False` — это `0`,
> и оба значения — синглтоны, существующие в единственном экземпляре за все
> время работы программы. Хороший тон работы с `bool` — не сравнивать
> значения через `==` и не делать явных приведений в условиях.

---

## 1. Способы создания

### Литералы `True` и `False`

```python
is_active = True
is_deleted = False
```

`True` и `False` — это **ключевые слова** языка (как `if` или `for`), а не
просто имена встроенных объектов, поэтому их нельзя случайно
переопределить.

### Конструктор `bool()`

Встроенный объект `bool()` конструирует логический объект на базе других объектов
по правилам **проверки истинности** (truth value testing) — они уже разбирались в
контексте условий `if`/`while` на предыдущем занятии:

```python
bool(1)        # True
bool(0)        # False
bool(-5)       # True   -- любое ненулевое число истинно
bool("")       # False  -- пустая строка ложна
bool("hello")  # True
bool([])       # False  -- пустой список ложен
bool([0])      # True   -- список из одного элемента непустой -> истинен
bool(None)     # False
```

---

## 2. `bool` — подтип `int`

`bool` — не отдельный, самостоятельный тип, а **подтип `int`**: у него
только два возможных значения, `True` и `False`, которые ведут себя как
`1` и `0` соответственно.

```python
isinstance(True, int)   # True -- bool -- это int

True == 1   # True
False == 0  # True

True + True                     # 2 -- bool участвует в арифметике как int
True + 1                        # 2
sum([True, False, True, True])  # 3 -- удобный способ посчитать "истинные" элементы
```

Поскольку отдельного диапазона значений или литералов чисел (десятичных,
двоичных и т. д.) у `bool` нет — значений всего два, и оба они создаются
либо напрямую (`True`/`False`), либо с помощью `bool()`.

---

## 3. Синглтоны `True` и `False`

`True` и `False` — **синглтоны**: в памяти программы существует ровно один
объект `True` и ровно один объект `False`, сколько бы раз они ни
"создавались" в коде. Любое новое "создание" `True` на самом деле не
создает новый объект, а лишь возвращает ссылку на уже существующий.

```python
flag_literal = True
flag_from_bool = bool(1)
flag_from_comparison = (5 > 3)

print(flag_literal is flag_from_bool)                                       # True -- один и тот же объект в памяти
print(flag_literal is flag_from_comparison)                                 # True
print(id(flag_literal) == id(flag_from_bool) == id(flag_from_comparison))   # True
```

Это же справедливо и для `False`. Именно поэтому для `bool`-значений (как
и для `None`) корректно и безопасно использовать оператор `is`.

---

## 4. Хороший тон работы с `bool`

### Не сравнивать через `==`

Если переменная уже содержит логическое значение (или результат
сравнения), сравнивать ее с `True`/`False` через `==` не нужно — само
значение уже является тем, что требуется проверить:

```python
is_valid = check_value(value)

# Плохо: избыточное сравнение

if is_valid == True:
    ...

# Хорошо: значение и так логическое

if is_valid:
    ...

# Аналогично для отрицания

if is_valid == False:  # плохо
    ...

if not is_valid:       # хорошо
    ...
```

Сравнение `== True` не только избыточно, но и менее надежно: если
`is_valid` вдруг окажется не `bool`, а, например, непустой строкой или
списком (truthy, но не равно `True`), сравнение `== True` даст `False`,
хотя в условии `if is_valid:` оно сработало бы верно.

### Не делать явных приведений в условиях

Внутри `if`/`while` и логических операторов Python сам приводит любое
значение к логическому по правилам проверки истинности — оборачивать
условие в `bool()` не нужно:

```python
items = get_items()

# Плохо: bool() внутри if избыточен

if bool(items):
    ...

# Хорошо

if items:
    ...
```

`bool()` стоит вызывать явно только тогда, когда логическое значение
нужно **как самостоятельный результат** — например, чтобы вернуть его из
функции или сохранить в переменную:

```python
def is_positive(number):
    return number > 0        # уже bool, оборачивать в bool() не нужно

has_items = bool(items)      # здесь bool() уместен: нужно именно значение
```

---

## Вывод

- `bool` создается литералами `True`/`False` или конструктором `bool()`
  (по правилам проверки истинности).
- `bool` — подтип `int`: `True` и `False` ведут себя как `1` и `0` и
  участвуют в арифметике.
- `True` и `False` — синглтоны: в памяти всегда ровно один объект на
  каждое значение, поэтому для них уместен оператор `is`.
- Хороший тон: не писать `if x == True` / `if x == False` (достаточно
  `if x:` / `if not x:`) и не оборачивать условия в `bool()` — Python и
  так приводит любое значение к логическому в контексте условия.
