# Арифметические операции над числовыми типами данных

> **Главная мысль.** Python поддерживает стандартный набор арифметических
> операций (`+ - * / // % **`). Числа с плавающей точкой из-за формата
> хранения дают погрешности вычислений. Составное присваивание
> (`+=`, `-=`, …) — это удобный синтаксис, но для неизменяемых числовых
> типов оно **не** меняет объект «на месте», а создает новый и
> перепривязывает к нему имя.

---

## 1. Набор арифметических операций

Python поддерживает все стандартные арифметические операции, используемые
в математике:

| Оператор | Значение | Пример |
|---|---|---|
| `+` | сложение | `2 + 3` -> `5` |
| `-` | вычитание | `5 - 3` -> `2` |
| `*` | умножение | `4 * 3` -> `12` |
| `/` | истинное деление | `7 / 2` -> `3.5` |
| `//` | целочисленное (floor) деление | `7 // 2` -> `3` |
| `%` | остаток от деления (modulo) | `7 % 2` -> `1` |
| `**` | возведение в степень | `2 ** 10` -> `1024` |
| унарный `-` / `+` | смена знака / без изменений | `-x`, `+x` |

---

## 2. Истинное деление

В отличие от многих языков программирования, где результат использования
оператора `/` с целыми числами дает целое число, в Python оператор `/`
— это оператор **истинного деления**. Его результат всегда является объектом
типа `float`, даже если числа делятся друг на друга нацело:

```python
7 / 2   # 3.5 -- float
6 / 2   # 3.0 -- тоже float, хотя делится без остатка
-7 / 2  # -3.5
```

---

## 3. Целочисленное и модульное деление

Оператор `//` называют оператором «целочисленного деления». Не стоит путать
операцию целочисленного деления с простым отбрасыванием дробной
части (как это происходит в `int()`). Результат целочисленного деления округляется
до ближайшего целого **вниз, к минус бесконечности (floor)**. Для положительных чисел
разница незаметна, а вот для отрицательных — принципиальна:

```python
7 // 2    # 3   -- 3.5 округляется вниз до 3, разницы с "отбрасыванием" нет
-7 // 2   # -4  -- а вот тут: -3.5 округляется вниз до -4, а не до -3!
7 // -2   # -4
-7 // -2  # 3
```

Оператор `%` — это оператор **модульного деления**: его результат —
остаток, который получается после выполнения целочисленного деления `//`.
Оператор `%` согласован с `//` так, чтобы всегда выполнялось тождество:

```
a == (a // b) * b + a % b
```

Из-за этого **знак результата `%` совпадает со знаком делителя** `b`, а
не делимого `a` (в отличие, например, от C или Java):

```python
7 % 2    # 1  -- обычный случай
-7 % 2   # 1  -- не -1! знак результата -- как у делителя (2 -- положительный)
7 % -2   # -1 -- знак -- как у делителя (-2 -- отрицательный)
-7 % -2  # -1
```

```python
# Проверка тождества a == (a // b) * b + a % b
dividend, divisor = -7, 2
print((dividend // divisor) * divisor + dividend % divisor)   # -7 -- тождество выполняется
```

> **Практическое следствие.** Если нужно именно "отбросить дробную
> часть" (округление к нулю, а не вниз), для отрицательных чисел `//` не
> подходит — там нужен `int(a / b)` или `math.trunc(a / b)`.

Несмотря на то что мы привыкли использовать операторы `//` и `%` с целыми
числами, в Python они работают не только с `int`, но и с `float`. Для чисел
с плавающей точкой справедлив тот же принцип округления вниз и то же тождество
`a == (a // b) * b + a % b`. Правда, на практике оператор `%` с `float`
используют крайне редко:

```python
7.5 // 2    # 3.0  -- floor от 3.75, но результат -- float
7.5 % 2     # 1.5  -- остаток тоже float
```

## 4. Погрешности вычислений с `float`

Числа с плавающей точкой хранятся в двоичном формате (IEEE 754), а многие
привычные десятичные дроби (например, `0.1`) **не представимы точно** в
двоичной системе — так же, как, например, 1/3 не представить точной конечной
десятичной дробью. Из-за этого возникают погрешности округления:

```python
0.1 + 0.2         # 0.30000000000000004, а не 0.3
0.1 + 0.2 == 0.3  # False -- прямое сравнение float на равенство ненадежно!
```

Это не «баг» Python — это особенность двоичного представления чисел с
плавающей точкой, характерная для подавляющего большинства языков
программирования.

**Правильный способ сравнения `float`** — сравнение с допустимой
погрешностью, а не с помощью оператора `==`:

```python
abs((0.1 + 0.2) - 0.3) < 1e-9  # True -- то же самое вручную
```

## 5. Приведение типов в операциях

Когда в одной арифметической операции участвуют значения разных числовых
типов, Python сам приводит их к «самому широкому» типу из участвующих —
в соответствии с иерархией `bool -> int -> float -> complex` (см. первый
конспект), и результат получает именно этот, более широкий тип:

```python
True + 1             # 2      -- bool + int -> int
True + 1.0           # 2.0    -- bool + float -> float
1 + 2.0              # 3.0    -- int + float -> float
1 + 2.0 + (1 + 1j)   # (4+1j) -- + complex -> complex
```

Однако такое приведение справедливо только для встроенных числовых типов.
Со строками, например, это уже не сработает: неявного приведения `str` к
числу в арифметике **нет** — Python строгий в типизации (см. конспект
первого занятия про характеристики языка):

```python
"2" + 3     # TypeError: can only concatenate str (not "int") to str
```

## 6. Составное присваивание

Чтобы изменить значение переменной на основе ее текущего значения, можно
явно вычислить новое значение и перепривязать к нему имя переменной:

```python
value = 5
value = value + 3   # value стало 8
```

Составное присваивание — это сокращенная запись той же самой операции
«вычислить новое значение и перепривязать имя»:

```python
value = 5
value += 3   # эквивалент value = value + 3
value -= 1   # эквивалент value = value - 1
value *= 2   # эквивалент value = value * 2
value /= 4   # эквивалент value = value / 4
value //= 2  # эквивалент value = value // 2
value %= 3   # эквивалент value = value % 3
value **= 2  # эквивалент value = value ** 2
```

### Числа неизменяемы

Числовые типы данных (`int`, `float`, `bool`) **неизменяемые (immutable)**.
Составное присваивание может выглядеть как «изменение объекта на месте»,
но на самом деле это не так: `x += 3` не меняет значение существующего
объекта, а создает новый объект со значением `x + 3` и **перепривязывает**
имя `x` к нему.

```python
value = 5
print(id(value))     # например, 140713...944 -- идентичность объекта 5

value += 3
print(value)      # 8
print(id(value))  # СОВЕРШЕННО ДРУГОЙ id -- это уже другой объект!
```

Убедиться в этом можно и через `is`:

```python
value = 5
old_value = value

value += 3

print(value is old_value)   # False -- value теперь ссылается на другой объект
```

---

## Вывод

- `/` — истинное деление, всегда возвращает `float`.
- `//` — деление с округлением **вниз** (floor), а не отбрасыванием
  дробной части; для отрицательных чисел это дает не такой результат, как
  «наивное» отбрасывание.
- `%` согласован с `//`: знак результата совпадает со знаком делителя, и
  всегда выполняется `a == (a // b) * b + a % b`.
- `float` из-за двоичного представления дает погрешности вычислений;
  сравнивать `float` нужно не через `==`, а через сравнение с допустимой погрешностью.
- В смешанных операциях типы приводятся по иерархии `bool -> int -> float -> complex`.
- Составное присваивание (`+=` и т. п.) для чисел — это не изменение
  объекта на месте, а создание нового объекта и перепривязка имени: числа
  в Python неизменяемы, что подтверждается сравнением `id()` до и после.
