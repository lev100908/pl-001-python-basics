# Пространства имен и области видимости

> **Главная мысль.** **Пространство имен (namespace)** — это отображение
> «имя → объект»: по сути, словарь, в котором имена переменных, функций и
> классов связаны с объектами в памяти. В Python одновременно существует
> много пространств имен, и они **независимы**: одно и то же имя в разных
> пространствах может ссылаться на разные объекты. **Область видимости
> (scope)** — участок программы, в котором пространство имен доступно
> напрямую. Основные виды: **встроенная** (built-in), **уровня модуля**
> (глобальная), **уровня функции** (локальная) и **уровня вложенной
> функции**. Каждый вызов функции создает *новое* локальное пространство имен,
> которое исчезает, когда функция завершается.

---

## 1. Что такое пространство имен

Когда мы пишем `age = 25`, Python создает объект `25` и связывает с ним имя
`age`. Таблица таких связей и есть **пространство имен**. Для наглядности его
можно представить как словарь:

```python
# age = 25
# name = "Alice"
# пространство имен: {"age": 25, "name": "Alice"}
```

Для глобального пространства имен это не просто аналогия: его действительно
можно получить функцией `globals()`, которая возвращает обычный словарь.

```python
age = 25
name = "Alice"

print(globals()["age"])     # 25
print("name" in globals())  # True
```

Пространства имен создаются в разные моменты времени и живут разное время:

| Пространство имен | Когда создается | Когда удаляется |
|---|---|---|
| **Встроенное** (`print`, `len`, `int`, `ValueError`, ...) | при запуске интерпретатора | при завершении интерпретатора |
| **Глобальное** (уровня модуля) | при загрузке модуля (запуске скрипта) | при завершении программы |
| **Локальное** (уровня функции) | при **каждом вызове** функции | при завершении этого вызова |

---

## 2. Независимость пространств имен

Главное свойство пространств имен — они **независимы**: одно и то же имя в
двух разных пространствах не имеет между собой ничего общего. Это означает,
что в разных функциях можно использовать одинаковые имена переменных и не
опасаться конфликтов:

```python
def first_function() -> None:
    value = 10
    print("first:", value)


def second_function() -> None:
    value = "text"
    print("second:", value)


first_function()   # first: 10
second_function()  # second: text
```

В обеих функциях есть переменная `value`, но это две разные переменные в двух
разных локальных пространствах имен. Благодаря этому функции можно
разрабатывать независимо друг от друга, не заботясь о том, какие имена
использованы в остальном коде.

Независимость касается и разных **вызовов** одной функции: каждый вызов
получает собственное локальное пространство имен.

```python
def count_to(limit: int) -> int:
    counter = 0

    for i in range(limit):
        counter += 1

    return counter


print(count_to(3))  # 3
print(count_to(5))  # 5 -- counter снова начинается с 0
```

Локальные переменные «забываются» после завершения функции, поэтому между
вызовами они ничего не помнят.

## 3. Область видимости уровня модуля

Имена, созданные на верхнем уровне файла (вне функций и классов), относятся
к **глобальному пространству имен модуля**. Эти имена называют
**глобальными переменными**. Они доступны во всем модуле, в том числе и
внутри функций (для **чтения**):

```python
tax_rate = 0.2  # глобальная переменная


def calculate_price(price: float) -> float:
    return price * (1 + tax_rate)  # tax_rate берется из пространства модуля


print(calculate_price(100))  # 120.0
```

К глобальным именам относятся не только переменные, но и все, что создается
на верхнем уровне модуля: функции (`def`), классы (`class`), импортированные
модули (`import`).

Глобальное пространство имен — «общее» для всего модуля. Если функции
зависят от глобальных переменных, их поведение трудно предсказать: результат
зависит не только от аргументов, но и от текущего состояния модуля.
Поэтому хорошая практика — передавать нужные данные в функцию через
параметры, а не брать их из глобальной области.

## 4. Область видимости уровня функции

Имена, созданные внутри функции (параметры и переменные, которым присвоено
значение в теле), образуют **локальное пространство имен** функции. Сами эти
имена называются **локальными**. Локальные имена видны только внутри своей
функции — из кода модуля или других функций обратиться к ним нельзя:

```python
def calculate_total(price: float, count: int) -> float:
    total = price * count  # total -- локальная переменная
    return total


print(calculate_total(10, 3))  # 30

print(total)  # NameError: name 'total' is not defined
print(price)  # NameError: name 'price' is not defined
```

Параметры функции — тоже локальные переменные. Они создаются в момент вызова
и связываются с переданными аргументами.

Таким образом, **из модуля не видно, что находится внутри функции**: функция
ведет себя как «черный ящик», который принимает аргументы и возвращает
результат, а внутренние детали скрывает.

### Одинаковые имена в модуле и в функции

Если имя присваивается внутри функции, то Python создает *новую локальную
переменную*, даже если такое же имя уже есть в модуле. Глобальная переменная
при этом **не изменяется** — это разные имена в разных пространствах:

```python
message = "global"


def change_message() -> None:
    message = "local"  # создается НОВАЯ локальная переменная
    print("inside:", message)


change_message()            # inside: local
print("outside:", message)  # outside: global
```

Эту особенность часто называют **затенением (shadowing)**: локальное имя
«закрывает» одноименное внешнее на время работы функции.

### Параметры и локальные переменные не пересекаются с глобальными

Аналогично работают и параметры: имя параметра — локальное, поэтому
совпадение с глобальным именем не приводит к конфликту, но может запутать
читателя. Старайтесь не использовать для параметров и локальных переменных те
же имена, что и у глобальных.

## 5. Область видимости уровня вложенной функции

Функции можно определять внутри других функций. Такая **вложенная
функция** создается заново при каждом вызове внешней функции и имеет
собственное локальное пространство имен. У вложенных функций действуют
следующие правила видимости:

- **из модуля** не видно ни локальных имен внешней функции, ни вложенной
  функции;
- **из внешней функции** не видно, что находится внутри вложенной функции;
- **из вложенной функции** видно (для чтения) все: ее собственные локальные
  имена, локальные имена объемлющей (внешней) функции и глобальные имена
  модуля.

```python
global_value = "global"


def outer() -> None:
    outer_value = "outer"

    def inner() -> None:
        inner_value = "inner"

        print(inner_value)   # inner  -- свое локальное имя
        print(outer_value)   # outer  -- имя внешней функции
        print(global_value)  # global -- имя модуля

    inner()

    print(outer_value)   # outer
    print(global_value)  # global
    print(inner_value)   # NameError: name 'inner_value' is not defined


outer()
```

Схематично это можно изобразить как вложенные «ящики», где видимость
направлена **изнутри наружу**:

```
┌─ модуль ─────────────────────────────────────┐
│ global_value                                 │
│  ┌─ outer ─────────────────────────────────┐ │
│  │ outer_value                             │ │
│  │  ┌─ inner ───────────────────────────┐  │ │
│  │  │ inner_value                       │  │ │
│  │  │ видит: inner, outer, модуль       │  │ │
│  │  └───────────────────────────────────┘  │ │
│  │ видит: outer, модуль                    │ │
│  └─────────────────────────────────────────┘ │
│ видит: только модуль                         │
└──────────────────────────────────────────────┘
```

Сама вложенная функция `inner` — это локальное имя внутри `outer`, поэтому
из модуля ее вызвать нельзя:

```python
inner()  # NameError: name 'inner' is not defined
```

занятий.

## Вывод

- **Пространство имен** — отображение «имя → объект» (по сути, словарь). В
  программе одновременно существует много независимых пространств имен:
  встроенное, глобальное (модуля) и локальные (функций).
- Одно и то же имя в разных пространствах никак не связано: присваивание
  внутри функции создает *новую* локальную переменную и не изменяет
  глобальную. Каждый вызов функции получает собственное локальное
  пространство имен, которое исчезает после завершения вызова.
- **Область видимости модуля** — глобальные имена видны во всем модуле, в том
  числе внутри функций (для чтения). **Область видимости функции** —
  локальные имена видны только внутри функции.
- Для вложенных функций видимость направлена **изнутри наружу**: вложенная
  функция видит имена внешней функции и модуля, но модуль не видит имен
  функции, а внешняя функция — имен вложенной.
