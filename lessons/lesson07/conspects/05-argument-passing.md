# Передача аргументов в функцию

> **Главная мысль.** В Python аргументы передаются в функцию **по ссылке на
> объект** (иначе — *call by object reference* или *call by sharing*). При
> вызове функции параметр становится новым именем, которое ссылается на **тот
> же самый объект**, что и переданный аргумент: копирование значения не
> происходит. Поэтому: (1) **изменяемый** объект (список, словарь, множество),
> измененный внутри функции «на месте», изменится и для вызывающего кода; (2)
> **присваивание** параметру нового значения лишь перенаправляет локальное имя
> на другой объект и снаружи незаметно; (3) **неизменяемые** объекты (числа,
> строки, кортежи) изменить внутри функции невозможно вообще.

---

## 1. Что происходит при вызове функции

Передача аргумента — это обычное **присваивание**: параметр функции
связывается с объектом, переданным в качестве аргумента, — ровно так же, как
при выполнении `parameter = argument`. Копия объекта не создается. Убедиться в этом можно с
помощью функции `id()`, которая возвращает идентичность объекта:

```python
def show_identity(parameter: list[int]) -> None:
    print("inside:", id(parameter))


numbers = [1, 2, 3]

print("outside:", id(numbers))
show_identity(numbers)
```

Вывод (конкретные числа будут другими, но два значения совпадут):
```
outside: 140234567890123
inside: 140234567890123
```

Имя `numbers` в вызывающем коде и имя `parameter` в функции — два разных имени
(в разных пространствах имен), которые ссылаются на **один и тот же объект**:

```
Вызывающий код              Функция
numbers   ────────┐
                  ├──►  [1, 2, 3]
parameter ────────┘
```

Эту модель называют по-разному: «передача по ссылке на объект», «передача по
разделению» (*call by sharing*). Ее не стоит путать с двумя другими моделями,
которые знакомы по другим языкам:

- **передача по значению** — функция получила бы *копию* объекта, и любые
  изменения не затрагивали бы оригинал. В Python копии не создаются;
- **передача по ссылке на переменную** (как `&` в C++) — функция могла бы
  перепривязать *переменную вызывающего кода* к другому объекту. В Python
  параметр — это самостоятельное имя, и перепривязка его не затрагивает имя
  снаружи.

Поведение зависит от того, **изменяемый** объект передан или нет, и от того,
что функция с ним делает — изменяет на месте или присваивает заново.

## 2. Изменяемые объекты: изменение «на месте» видно снаружи

Если внутри функции изменить переданный изменяемый объект методом или
операцией присваивания по индексу/ключу, изменения увидит и вызывающий код —
ведь объект один и тот же:

```python
def add_item(items: list[str], item: str) -> None:
    items.append(item)


shopping_list = ["bread", "milk"]

add_item(shopping_list, "eggs")

print(shopping_list)  # ['bread', 'milk', 'eggs']
```

То же самое справедливо для словарей и множеств:

```python
def set_default_language(settings: dict[str, str]) -> None:
    settings["language"] = "en"


user_settings = {"theme": "dark"}

set_default_language(user_settings)

print(user_settings)  # {'theme': 'dark', 'language': 'en'}
```

Параметр функции и переменная в вызывающем коде ссылаются на один и тот же
объект. Поэтому функция может не только читать переданный объект, но и
изменять его, а изменение будет видно в вызывающем коде (в примерах выше —
через `shopping_list` и `user_settings`). Иногда это нужно (так работает
`list.sort()` или функция, заполняющая переданный список), но чаще становится
источником неожиданных побочных эффектов: функция изменяет данные, которые
не должна была изменять.

Если функция не должна менять исходные данные, она должна работать с
**копией**:

```python
def get_sorted_copy(numbers: list[int]) -> list[int]:
    numbers_copy = numbers.copy()

    numbers_copy.sort()

    return numbers_copy


original = [3, 1, 2]
result = get_sorted_copy(original)

print(original)  # [3, 1, 2] -- не изменился
print(result)    # [1, 2, 3]
```

Нужно помнить, что `copy()` создает **поверхностную** копию: вложенные
изменяемые объекты по-прежнему будут общими. Для глубокого копирования
используется `copy.deepcopy()`.

## 3. Присваивание параметру: перепривязка имени

Присваивание `parameter = new_value` внутри функции **не изменяет** объект, на
который указывал параметр. Оно лишь заставляет *локальное имя* ссылаться на
другой объект. Имя в вызывающем коде при этом остается связанным со старым
объектом:

```python
def replace_list(items: list[int]) -> None:
    items = [100, 200]  # локальное имя items теперь указывает на новый список

    print("inside:", items)


numbers = [1, 2, 3]

replace_list(numbers)

print("outside:", numbers)
```

Вывод:
```
inside: [100, 200]
outside: [1, 2, 3]
```

Схематично:

```
До присваивания:       numbers ─┬─► [1, 2, 3]
                       items   ─┘

После items = [...]:   numbers ───► [1, 2, 3]
                       items   ───► [100, 200]
```

Сравним два варианта внутри функции — изменение на месте и перепривязка:

```python
def append_in_place(items: list[int]) -> None:
    items.append(4)       # изменяем объект -- видно снаружи


def append_by_rebinding(items: list[int]) -> None:
    items = items + [4]   # создаем НОВЫЙ список и перепривязываем items


first_list = [1, 2, 3]
second_list = [1, 2, 3]

append_in_place(first_list)
append_by_rebinding(second_list)

print(first_list)   # [1, 2, 3, 4]
print(second_list)  # [1, 2, 3]
```

Особую осторожность требует оператор `+=`. Для изменяемых объектов
он выполняет изменение **на месте**, поэтому результат отличается от
`items = items + [...]`:

```python
def extend_with_augmented(items: list[int]) -> None:
    items += [4]  # для списка -- то же, что items.extend([4]): изменение на месте


numbers = [1, 2, 3]

extend_with_augmented(numbers)

print(numbers)  # [1, 2, 3, 4]
```

## 4. Неизменяемые объекты: изменить нельзя

Числа, строки, кортежи, `bool`, `None`, `frozenset` — **неизменяемые**.
Любая операция, которая «меняет» такой объект, на самом деле создает **новый**
объект. Значит, изнутри функции изменить значение, переданное вызывающим
кодом, нельзя:

```python
def increase(number: int) -> None:
    number += 10  # создается новое число 15, локальное имя number указывает на него

    print("inside:", number)


value = 5

increase(value)

print("outside:", value)
```

Вывод:
```
inside: 15
outside: 5
```

Аналогично со строками:

```python
def make_upper(text: str) -> None:
    text = text.upper()  # новая строка, оригинал не тронут


message = "hello"

make_upper(message)

print(message)  # hello
```

Если нужно получить измененное значение, функция должна **вернуть его через
`return`**, а вызывающий код — сохранить результат:

```python
def increase(number: int) -> int:
    return number + 10


value = 5
value = increase(value)

print(value)  # 15
```

Кортеж неизменяем, но он может содержать изменяемые элементы — менять *их*
можно, как и в любом другом контексте:

```python
def append_to_first(data: tuple[list[int], int]) -> None:
    data[0].append(99)  # изменяется список внутри кортежа


pair = ([1, 2], 3)

append_to_first(pair)

print(pair)  # ([1, 2, 99], 3)
```

## 5. Итоговая таблица

| Тип объекта | Что делает функция | Видно ли снаружи |
|---|---|---|
| Изменяемый (`list`, `dict`, `set`) | изменяет на месте (`append`, `items[key] = ...`, `update`, `+=`) | **да** |
| Изменяемый | присваивает параметру новый объект (`items = [...]`) | нет |
| Неизменяемый (`int`, `str`, `tuple`, ...) | любая «модификация» | нет (создается новый объект) |

Практические рекомендации:

- если функция **только читает** переданные данные, побочных эффектов у нее
  нет;
- если функция **изменяет** переданный объект на месте, это нужно явно
  указать в имени и в документации (`fill_list`, `sort_in_place`). Такая
  функция, как правило, ничего не возвращает, то есть возвращает `None`
  (так ведут себя `list.sort()` и `list.append()`);
- если нужен **новый результат**, создайте копию (или новый объект) внутри
  функции и верните его через `return` — переданный объект при этом не
  изменяется.

---

## Вывод

- Аргументы передаются **по ссылке на объект**: параметр — новое имя,
  ссылающееся на тот же объект, что и аргумент. Копия не создается
  (проверить можно через `id()`).
- Изменение изменяемого объекта на месте (`append`, `update`, присваивание по
  индексу или ключу, `+=` для списка) видно вызывающему коду.
- Присваивание параметру нового значения не затрагивает переменную в
  вызывающем коде — меняется только локальное имя.
- Неизменяемые объекты внутри функции изменить нельзя: «изменение»
  порождает новый объект. Чтобы передать результат наружу, используйте
  `return`.
- Чтобы не менять исходные данные, работайте с копией.
