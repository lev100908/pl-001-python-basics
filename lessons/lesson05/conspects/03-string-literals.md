# Строковые литералы

> **Главная мысль.** Строковый литерал — это запись строки прямо в коде. Его
> можно заключить как в **одинарные**, так и в **двойные** кавычки — это
> равнозначные способы, которые нужны, чтобы без лишних усилий записывать
> кавычки внутри текста. Текст на нескольких строках записывают с помощью
> **тройных кавычек**. Соседние литералы, стоящие рядом, автоматически
> склеиваются в один.

---

## 1. Одинарные и двойные кавычки

Строковый литерал записывается в кавычках — одинарных `'...'` или
двойных `"..."`. Для интерпретатора эти варианты **полностью
равнозначны**: результат — один и тот же объект типа `str`:

```python
single_quoted = 'hello'
double_quoted = "hello"

print(single_quoted == double_quoted)  # True
print(type(single_quoted))             # <class 'str'>
print(type(double_quoted))             # <class 'str'>
```

Отдельного литерала для одного символа нет: `'a'` — такая же строка, как и
`'abc'`, только длины `1`.

### Зачем нужны два вида кавычек

Два вида кавычек позволяют записывать **кавычки внутри текста без
экранирования**: достаточно оформить литерал кавычками другого вида,
отличными от тех, что встречаются внутри:

```python
print("It's a sunny day")  # It's a sunny day
print('He said: "Hello"')  # He said: "Hello"
```

Если в тексте встречаются кавычки обоих видов, внутри литерала их
приходится экранировать с помощью обратного слеша (см. конспект про
escape-символы):

```python
print('It\'s "quoted"')  # It's "quoted"
```

Какой вид кавычек выбрать — вопрос договоренности в команде. PEP 8 не
отдает предпочтение ни одному из видов и рекомендует лишь **придерживаться
единого стиля** в пределах проекта и выбирать такой вид кавычек, чтобы
избежать обратных слешей внутри строки. В этом курсе мы используем
двойные кавычки (именно их по умолчанию выбирают популярные
форматтеры, например, `black`).

### Пустая строка

Пустая строка — литерал без символов между кавычками. Она ложна (falsy),
в отличие от любой непустой строки:

```python
empty_string = ""

print(len(empty_string))   # 0
print(bool(empty_string))  # False
print(bool(" "))           # True -- строка из одного пробела уже не пустая
```

### Литерал не может переноситься на другую строку

Литерал в одинарных или двойных кавычках обязан **начинаться и заканчиваться
на одной физической строке** файла. Если нажать `Enter` внутри такого
литерала, интерпретатор сообщит об ошибке:

```python
message = "first line
second line"
# SyntaxError: unterminated string literal (detected at line 1)
```

Для текста на нескольких строках есть два способа: тройные кавычки и
escape-символ `\n` (см. следующий конспект).

## 2. Многострочные литералы: тройные кавычки

Если заключить текст в **тройные** кавычки — `"""..."""` или `'''...'''`,
— литерал может занимать **несколько физических строк**. Все переводы
строк и пробелы внутри сохраняются в строке **как есть**:

```python
poem = """Roses are red,
Violets are blue."""

print(poem)
print(repr(poem))  # 'Roses are red,\nViolets are blue.'
```

Вывод `print(poem)`:
```
Roses are red,
Violets are blue.
```

Внутри тройных кавычек свободно используются как одинарные, так и
двойные кавычки — экранировать их не нужно (достаточно не ставить подряд
три кавычки того же вида, которыми литерал открыт):

```python
quote = """He said: "It's fine" and left."""

print(quote)  # He said: "It's fine" and left.
```

### Перевод строки после открывающих кавычек

Если текст начинается сразу на следующей строке после открывающих кавычек,
первым символом строки окажется перевод строки — `\n`:

```python
text = """
first
second
"""

print(repr(text))  # '\nfirst\nsecond\n'
```

Чтобы этого избежать, перед переводом строки ставят обратный слеш — он
«экранирует» перевод строки, и тот в литерал не попадает:

```python
text = """\
first
second"""

print(repr(text))  # 'first\nsecond'
```

### Отступы становятся частью строки

Внутри тройных кавычек пробелы в начале строк — тоже символы текста.
Поэтому, если записать литерал внутри функции или цикла с отступом, эти
отступы окажутся внутри строки:

```python
def get_help() -> str:
    return """Usage:
    run --fast
    run --slow"""

print(get_help())
```

Вывод:
```
Usage:
    run --fast
    run --slow
```

## 3. Неявная конкатенация соседних литералов

Если два (или больше) строковых литерала записаны **рядом**, разделенные
только пробелами или переводами строк, интерпретатор склеивает их в **один**
литерал еще на этапе разбора программы — никакого оператора для этого не
нужно:

```python
text = "hello, " "world"

print(text)  # hello, world
```

Этот прием удобен для **длинных строк**: литерал можно разбить на части
в круглых скобках — перевод строки внутри скобок допустим — и сохранить
при этом читаемость:

```python
long_message = (
    "This is a very long message, "
    "which is split into several lines "
    "to keep the code readable."
)

print(long_message)
# This is a very long message, which is split into several lines to keep the code readable.
```

Эта же особенность — источник коварной ошибки: если **забыть запятую**, например,
между элементами списка, соседние литералы тихо склеятся в один элемент и
ошибки не будет:

```python
fruits = [
    "apple",
    "banana"
    "cherry",
]

print(fruits)       # ['apple', 'bananacherry']
print(len(fruits))  # 2 -- а не 3
```

---

## Вывод

- Строковые литералы записываются в одинарных `'...'` или двойных `"..."`
  кавычках — это равноправные способы; вид кавычек выбирают так, чтобы
  не экранировать кавычки внутри текста, и придерживаются единого стиля.
- Литерал в простых кавычках должен умещаться на одной физической строке.
- Тройные кавычки (`"""..."""`, `'''...'''`) позволяют записать текст на
  нескольких строках: переводы строк и отступы сохраняются как есть.
- Соседние литералы склеиваются в один — это удобно для длинных строк
  (в скобках), но легко приводит к ошибке при пропущенной запятой.
