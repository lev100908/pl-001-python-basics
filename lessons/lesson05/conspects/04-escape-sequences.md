# Escape-символы

> **Главная мысль.** Некоторые символы невозможно или неудобно записать в
> литерале «как есть»: перевод строки, табуляцию, кавычку того же вида, что
> и у литерала, и сам обратный слеш. Для них придуманы **escape-последовательности**
> — комбинации из обратного слеша `\` и следующего за ним символа. Еще
> на этапе разбора программы интерпретатор заменяет такую комбинацию
> **одним** символом, поэтому `len("\n")` равно `1`, а не `2`.

---

## 1. Мотивация

Обратный слеш `\` внутри строкового литерала — **служебный символ**: он
сообщает интерпретатору, что следующий за ним символ нужно понимать
особым образом. Это решает сразу несколько проблем:

- литерал в простых кавычках нельзя перенести на следующую строку — но
  как тогда записать **перевод строки**?
- как записать **кавычку** того же вида, которой литерал ограничен — не
  закончится ли литерал раньше времени?
- как записать **невидимые** управляющие символы — табуляцию, возврат
  каретки?
- раз `\` — служебный символ, как записать сам **обратный слеш**?

```python
print(len("\n"))    # 1 -- два символа в коде, один символ в строке
print(len("\\"))    # 1
print(len("a\tb"))  # 3
```

## 2. Основные escape-последовательности

| Запись | Символ |
|---|---|
| `\n` | перевод строки (line feed) |
| `\t` | горизонтальная табуляция |
| `\\` | обратный слеш |
| `\'` | одинарная кавычка |
| `\"` | двойная кавычка |
| `\v` | вертикальная табуляция |
| `\b` | возврат на один символ (backspace) |
| `\r` | возврат каретки (carriage return) |

Рассмотрим подробнее каждую из них, кроме `\\`: обратный слеш вынесен в
отдельный раздел в конце конспекта. Чтобы результат не зависел от того,
как терминал отображает управляющие символы, часть примеров ниже
выводится через `repr()`.

### `\n` — перевод строки

Самая часто используемая последовательность: заставляет следующий текст
начаться с новой строки. Именно `\n` по умолчанию добавляет в конец
вывода функция `print()`:

```python
print("first\nsecond")
```

Вывод:
```
first
second
```

### `\t` — табуляция

Горизонтальная табуляция «перепрыгивает» к следующей позиции табуляции —
так можно выравнивать текст в столбцы (хотя для таблиц надежнее использовать
форматирование — см. соответствующий конспект):

```python
print("name\tage")
print("Alice\t30")
```

Вывод (ширина табуляции зависит от терминала, обычно — 8 символов):
```
name    age
Alice   30
```

### `\'` и `\"` — кавычки

Позволяют записать кавычку того же вида, что и обрамляющая, не закончив
литерал раньше времени:

```python
print('It\'s a sunny day')   # It's a sunny day
print("He said: \"Hello\"")  # He said: "Hello"
```

Когда это возможно, лучше выбрать для литерала другой вид кавычек, чем
использовать экранирование (см. конспект про литералы).

### `\v`, `\b` и `\r` — управляющие символы терминала

Эти символы пришли из эпохи пишущих машинок и телетайпов и управляют
положением курсора. В современном коде используются редко, а их
отображение зависит от конкретной программы, в которой выводится текст
(терминал, консоль IDE, файл), поэтому для наглядности посмотрим на их
представление через `repr()`:

```python
print(repr("a\vb"))  # 'a\x0bb'
print(repr("a\bb"))  # 'a\x08b'
print(repr("a\rb"))  # 'a\rb'
```

Обратите внимание: `repr()` показывает `\v` и `\b` в виде **шестнадцатеричных
кодов** `\x0b` и `\x08`, потому что у них нет «коротких» популярных
записей, как у `\n` и `\t`.

- **`\v` (vertical tab)** — вертикальная табуляция: в терминале обычно
  перемещает курсор на строку вниз, не возвращая его в начало строки.
  Практически не используется в обычных программах, но важно знать, что
  Python считает ее **пробельным символом** (на это реагируют методы
  `isspace()`, `strip()`, `split()`, `splitlines()`).
- **`\b` (backspace)** — перемещает курсор на один символ влево, поэтому
  следующий символ затирает предыдущий:

  ```python
  print("abc\bd")  # abd -- в большинстве терминалов буква "c" будет затерта
  ```

- **`\r` (carriage return)** — возвращает курсор **в начало текущей
  строки**, не переходя на новую. Так текст можно перезаписывать «на
  месте» — например, для индикатора прогресса:

  ```python
  print("Loading: 10%", end="\r")
  print("Loading: 20%", end="\r")
  print("Loading: 100%")
  ```

  Каждый следующий вывод затирает предыдущий в той же строке (в итоге
  на экране останется только `Loading: 100%`). В файле такие символы
  останутся лишь «мусором», поэтому прием работает только при выводе в
  терминал.

### `\\` — обратный слеш

Так как `\` — служебный символ, чтобы получить сам обратный слеш, его
нужно **удвоить**. Типичный случай — пути к файлам в Windows:

```python
path = "C:\\Users\\Alice\\notes.txt"

print(path)  # C:\Users\Alice\notes.txt
```

Если же записать путь «как есть», `\U`, `\n`, `\t` и другие комбинации
будут восприняты как escape-последовательности — и результат окажется не
таким, как ожидалось:

```python
print("C:\new\table")
```

Вывод:
```
C:
ew     able
```

Здесь `\n` превратился в перевод строки, а `\t` — в табуляцию. Удваивать
каждый слеш вручную неудобно и легко ошибиться, особенно когда обратных
слешей в тексте много. Для таких случаев в Python есть специальный вид
литералов — **r-строки**, которые отключают обработку escape-последовательностей.
Их разберем в следующем конспекте.

## Вывод

- **Escape-последовательность** — обратный слеш `\` и символ после него.
  Интерпретатор заменяет ее **одним** символом при разборе литерала.
- Они нужны, чтобы записать то, что нельзя или неудобно ввести напрямую:
  перевод строки `\n`, табуляцию `\t`, кавычки `\'` и `\"`, а также сам
  обратный слеш `\\`.
- `\r`, `\b` и `\v` управляют курсором терминала; в обычных программах
  используются редко. Проверить, какие символы реально лежат в строке,
  помогает `repr()`.
- Путь вида `"C:\new\table"` без удвоения слешей **ломается**, потому что
  `\n` и `\t` — это escape-последовательности. Для таких случаев
  существуют r-строки.
