# Специальные строки: r-строки, f-строки, t-строки

> **Главная мысль.** Перед открывающей кавычкой литерала можно поставить
> **префикс**, который меняет правила разбора этого литерала. Префикс `r`
> отключает обработку escape-последовательностей — это **r-строка** (raw,
> «сырая»; удобна для путей и регулярных выражений). Префикс `f` включает
> в строку значения выражений — это **f-строка** (удобная замена склейке и
> `str()`). В Python 3.14 добавлены еще и **t-строки** — «шаблоны», которые
> не превращаются в строку сразу. Важно: r- и f-строки — это просто разные
> способы **записать** литерал, результатом всегда является обычный объект `str`.

---

## 1. r-строки (raw strings)

### Мотивация

Как мы видели в конспекте про escape-символы, обратный слеш в обычной
строке — служебный. Но существуют случаи, когда обратных слешей в тексте
много и все они — **обычные символы**:

- пути к файлам в Windows: `C:\new\table`;
- регулярные выражения (модуль `re`): `\d+\.\d+`.

Удваивать каждый слеш неудобно и легко ошибиться. **r-строка** (raw —
«сырая») — литерал с префиксом `r` (или `R`) — **не обрабатывает
escape-последовательности**: каждый обратный слеш остается в строке как
самостоятельный символ.

```python
regular_path = "C:\\new\\table"
raw_path = r"C:\new\table"

print(raw_path)                  # C:\new\table
print(regular_path == raw_path)  # True -- это одна и та же строка
print(len(r"\n"))                # 2 -- обратный слеш и буква n
```

### Особенности и ограничения

Несмотря на «сырость», обратный слеш по-прежнему взаимодействует с
кавычками: он **не дает кавычке завершить литерал**, но при этом сам
остается в строке. Поэтому r-строка **не может заканчиваться нечетным
количеством обратных слешей**:

```python
print(r"say \"hi\"")  # say \"hi\" -- слеши остались в строке

print(r"C:\folder\")
# SyntaxError: unterminated string literal -- \" не закрыл литерал
```

Типичный выход — склеить r-строку с обычной (неявная конкатенация):

```python
folder = r"C:\folder" "\\"

print(folder)  # C:\folder\
```

### Комбинация с другими префиксами

Префиксы можно комбинировать: `rf"..."` (или `fr"..."`) — это
r-строка, в которой работают подстановки из f-строки (о них — в следующем разделе):

```python
folder = "reports"
file_name = "2024.txt"

print(rf"C:\data\{folder}\{file_name}")  # C:\data\reports\2024.txt
```

## 2. f-строки (formatted string literals)

### Мотивация

Очень часто нужно собрать текст из нескольких частей и значений разных
типов. Конкатенация через `+` требует вручную вызывать `str()` для чисел и
быстро превращается в нечитаемую «лесенку» кавычек и плюсов:

```python
name = "Alice"
age = 30

print("Name: " + name + ", age: " + str(age))  # Name: Alice, age: 30
```

**f-строка** (от *formatted*) решает эту проблему: перед открывающей
кавычкой ставится префикс `f` (или `F`), а значения, которые нужно подставить,
записываются прямо внутри текста в фигурных скобках:

```python
name = "Alice"
age = 30

print(f"Name: {name}, age: {age}")  # Name: Alice, age: 30
```

Запись получается короче и ближе к тому, как выглядит итоговый текст.
Приводить значения к строке вручную не нужно — это делает сама f-строка (с
помощью `str()`).

### Что можно писать внутри `{}`

Внутри фигурных скобок записывается **произвольное выражение** Python. Оно
вычисляется **в момент выполнения** строки, а его результат подставляется в
текст:

```python
price = 120
quantity = 3
name = "alice"

print(f"Total: {price * quantity}")                 # Total: 360
print(f"Name: {name.upper()}")                      # Name: ALICE
print(f"Even: {quantity % 2 == 0}")                 # Even: False
print(f"Status: {'ok' if price > 100 else 'low'}")  # Status: ok
```

Обратите внимание на последнюю строку: внутри f-строки, ограниченной
двойными кавычками, строки в выражении нужно писать в **одинарных**
кавычках (в версиях Python до 3.12 использовать те же кавычки внутри
выражения нельзя; в 3.12 это ограничение сняли, но привычка выбирать
разные кавычки сохраняет читаемость и совместимость).

### Фигурные скобки как обычные символы

Чтобы вывести саму фигурную скобку, ее **удваивают**:

```python
value = 5

print(f"Set: {{{value}}}")  # Set: {5}
print(f"{{value}}")         # {value} -- скобки удвоены, подстановки нет
```

### Отладочный вывод: `{value=}`

Если после выражения поставить `=`, f-строка выведет **само выражение,
знак равенства и значение** (через `repr()`). Это удобно для быстрой
отладки без дублирования имени переменной:

```python
counter = 7
text = "hi"

print(f"{counter=}")        # counter=7
print(f"{text=}")           # text='hi'
print(f"{counter * 2 = }")  # counter * 2 = 14
```

### Флаги преобразования `!s`, `!r`, `!a`

Как было показано в конспекте про `str` и `repr`, после выражения можно
указать флаг преобразования: `!s` — `str()`, `!r` — `repr()`, `!a` —
`ascii()`:

```python
word = "hello\n"

print(f"{word!r}")  # 'hello\n'
```

### Спецификатор формата

После выражения через двоеточие можно указать **спецификатор формата** — он
управляет тем, как значение превращается в текст: число знаков после
запятой, ширина, выравнивание и другое. Эта возможность настолько
богатая, что ей посвящены отдельные конспекты:

```python
pi = 3.14159265

print(f"{pi:.2f}")  # 3.14
```

### Ограничение: f-строка вычисляется сразу

f-строка — это **не шаблон**, который можно заполнить позже: все
выражения внутри вычисляются **в момент**, когда выполняется строка
кода с f-строкой, и все имена должны быть к этому моменту определены:

```python
print(f"Hello, {user_name}!")
# NameError: name 'user_name' is not defined
```

Если нужно сначала описать шаблон, а подставить значения позже (или
подставлять в один шаблон много раз), используют метод `format()` (см.
конспект про форматирование) или t-строки (см. ниже).

## 3. t-строки (template strings, Python 3.14)

В **Python 3.14** (PEP 750) добавили еще один вид литералов — **t-строки**.
Внешне они похожи на f-строки (`t"Hello, {name}"`), но
есть принципиальное отличие: t-строка **не превращается в `str`**. Вместо
этого получается объект типа `Template` (модуль `string.templatelib`),
который **хранит отдельно** неизменяемые куски текста и подставляемые
значения.

```python
# Python 3.14+
name = "Alice"

greeting = t"Hello, {name}!"

print(type(greeting))  # <class 'string.templatelib.Template'>
```

Зачем это нужно? При обычной f-строке значения сразу «вклеиваются» в
текст, и информация о том, что было шаблоном, а что — данными, теряется.
Для безопасной сборки SQL-запросов, HTML и других текстов, в которых
значения нужно **экранировать или обрабатывать особым образом**, это
опасно (так возникают инъекции). С t-строкой функция-обработчик получает
шаблон целиком и может, например, экранировать каждое значение перед
тем, как собрать итоговую строку.

В рамках курса мы t-строки не используем (курс рассчитан на Python 3.12+,
а t-строки доступны только начиная с 3.14) — достаточно знать, что такая
возможность появилась и для чего она нужна.

## Вывод

- **r-строка** (`r"..."`) отключает обработку escape-последовательностей:
  удобна для путей Windows и регулярных выражений; не может заканчиваться
  нечетным числом обратных слешей.
- **f-строка** (`f"..."`) подставляет значения выражений из `{}` прямо в
  текст: короче и читаемее, чем `+` и `str()`. Выражение вычисляется в
  момент выполнения строки; `{{` и `}}` дают сами скобки; `{value=}`
  удобен для отладки; после `:` задается спецификатор формата.
- r- и f-строки — лишь способы записи литерала; результат — обычный `str`.
  Префиксы можно комбинировать: `rf"..."`.
- **t-строки** (`t"..."`, Python 3.14) дают объект `Template`, а не `str`, —
  чтобы значения можно было безопасно обработать перед сборкой текста.
